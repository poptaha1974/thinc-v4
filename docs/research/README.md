# خط البحث في THINC — التحديث الذاتي وسجل النظريات

**المبتكر والمالك:** الدكتور إيهاب طه (Dr. Ehab Taha).
**الحزمة:** `thinc_v4.research` (دخلت التوزيع في 4.4.0).

هذا الخط يجعل النموذج يتغذّى من الأبحاث المنشورة **بموافقة بشرية على كل تغيير**.
لا شيء هنا يعدّل النموذج تلقائيًا.

## الوحدات

| الوحدة | الدور | تلمس الشبكة؟ |
|---|---|---|
| `models` | `ResearchPaper`، `Theory`، `UpdateProposal`، `UpdateRun`، وأنواع الأدلة | لا |
| `evidence` | تصنيف قوة الدليل بهرم Cochrane (دوال نقية) | لا |
| `semantic_filter` | استبعاد الأوراق خارج السياق (طبية، رياضية، تقنية) | لا |
| `registry` | سجل النظريات ومخزن الأوراق بإزالة التكرار | لا |
| `proposals` | توليد الاقتراحات ومراجعتها وتطبيقها | لا |
| `ingestion` | OpenAlex وSemantic Scholar خلف `JsonFetcher` قابل للحقن | **نعم — الوحدة الوحيدة** |
| `auto_updater` | المنسّق ودورة التحديث وواجهة الأوامر | عبر `ingestion` |

## أين تُخزَّن الحالة

النظريات العشرة تُشحن **بيانات بذرة للقراءة فقط** داخل الحزمة
(`research/data/theories_seed.json`). حالة العمل تُكتب في مجلد قابل للكتابة:

```bash
export THINC_RESEARCH_DIR=~/thinc-research     # الافتراضي: ~/.thinc/research
```

نفس درس الأوزان المعايَرة: الحزمة المثبّتة تعيش في `site-packages` للقراءة فقط،
فلا تُكتب حالة داخلها.

الملفات المُنشأة: `theory_registry.json` · `papers.json` · `proposals.json` ·
`rejection_log.json` · `update_runs.json` · `cache/`.

## التشغيل

```bash
thinc-v4-research stats                  # حالة السجل والأوراق والمعلّق
thinc-v4-research run                     # دورة تحديث كاملة (تولّد اقتراحات معلّقة فقط)
thinc-v4-research run --max-queries 5     # دورة محدودة
thinc-v4-research pending                 # عرض الاقتراحات المعلّقة بمبرراتها
thinc-v4-research approve <id> --notes "معتمد"
thinc-v4-research reject <id> --notes "السياق غير مصري"
```

## دورة التحديث

1. **الاستعلامات** — لكل نظرية نشطة: اسمها **بين علامتي تنصيص** + ثلاثة سياقات
   (`consumer behavior`، `marketing`، `purchase decision`). التنصيص هو ما أوقف
   مطابقة أي ورقة تحتوي كلمة `loss` أو `social`.
2. **السحب** — OpenAlex أولًا؛ وSemantic Scholar احتياطيًا **فقط** لو جاءت النتائج
   أقل من ثلاث. أي استعلام يفشل يُسجَّل في `queries_failed` — المصدر المعطّل لا
   يبدو وكأنه "لا نتائج".
3. **الفلترة** — قائمة سوداء للكلمات والدوريات، بيضاء للدوريات السلوكية، وكلمات
   مطلوبة. كل رفض يُسجَّل بسببه.
4. **التصنيف** — هرم Cochrane: تحليل بَعدي (1.00) ← مراجعة منهجية (0.90) ←
   تجربة معشّاة (0.80) ← أترابية (0.60) ← مقطعية (0.40) ← رأي خبير (0.10)، مع
   مضاعف استشهادات ومضاعف حداثة.
5. **التخزين** — إزالة تكرار بالـDOI؛ التكرار يُحدّث عدد الاستشهادات تصاعديًا فقط.
6. **الاقتراحات** — أربعة أنواع: `evidence_update`، `new_theory`،
   `deprecate_theory`، `weight_change`. **كلها معلّقة.**

## قواعد محفوظة بالاختبارات

- **Human-in-the-Loop:** دورة كاملة لا تغيّر أي درجة؛ اختبار يثبّت ذلك.
- **اعتماد `evidence_update` يطبّق القيمة المُراجَعة** لا إعادة الحساب من نسبة
  المؤيدين — تلك الإعادة كانت تقفز بالثقة من 0.85 إلى 1.0 دفعة واحدة.
- **`weight_change` يمرّ بمخطط الأوزان القانوني**، ويُرفض أي تغيير يكسر مجموع 1.0
  مع ترك ملف الأوزان كما هو والاقتراح معلّقًا.
- **سجل غير قابل للقراءة يرفع خطأ** بدل أن يبدأ فارغًا فيُسقط كل النظريات بصمت.
- **لا شبكة في أي اختبار** — كل سحب يمرّ ببديل محلي مَحقون.
