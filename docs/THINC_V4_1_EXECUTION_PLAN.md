**النموذج:** THINC™ v4.0 → v4.1 "Calibrated Edition"
**المالك:** د. إيهاب طه — Egy-Pioneers Academy
**تاريخ الخطة:** يوليو 2026
**المدة الكلية:** 6 شهور (نواة صلبة خلال أول 90 يوم)

## الهدف الاستراتيجي

سد البقع العمياء الخمسة المكتشفة في مراجعة v4.0، بحيث يتحول THINC من نموذج
مبني على خبرة المؤسس إلى نموذج **يقيس دقة توقعاته ويعاير نفسه بالبيانات** —
نفس الفلسفة اللي بيعلّمها للطلاب (Reality Validation + Bayesian Updating)
مطبقة على النموذج ذاته.

> **مؤشر النجاح النهائي:** بعد 6 شهور، نقدر نقول بالأرقام:
> "درجة THINC بتتنبأ بنجاح مشروع الطالب بدقة X%، والأوزان اتعايرت على Y دفعة حقيقية."

**الهدف:** بناء **Outcome Tracking Registry** — العمود الفقري لكل اللي بعده.

- تجهيل هوية الطالب بهاش SHA-256 (`anonymize_student`)

**المتبقي تشغيلياً:**

## المرحلة 2 · محرك المعايرة البايزية (الأسبوع 6–10) — ✅ الكود جاهز

**المُنفَّذ في هذا الإصدار:** `src/thinc_v4/calibration.py` + `src/thinc_v4/weights.json`
- تقرير دقة تنبؤية: Accuracy / Precision / Recall / AUC + Calibration bins + ارتباط كل مكوّن بالنجاح
- معايرة بايزية: Prior = أوزان الخبرة، Likelihood = ارتباطات النتائج، قوة البيانات تتشبع عند 200 نتيجة
- حد أمان ±20% لكل وزن في الدورة + إعادة تطبيع للمجموع 1.0
- حد أدنى 25 نتيجة مكتملة للدورة الواحدة
- الأوزان خرجت من الكود إلى `weights.json` بإصدارات (`v4.0.0-prior` → `v4.1.0-c1`...)
- كل تقرير THINC بيحمل `model_version` + `weights_version`

**CLI:**
```bash
python -m thinc_v4.calibration --report --data-dir data/
python -m thinc_v4.calibration --calibrate --data-dir data/ --dry-run
```

**المتبقي تشغيلياً:** تقرير معايرة ربع سنوي أوتوماتيك يتراجع من د. إيهاب قبل اعتماد الأوزان.

## المرحلة 3 · الاختبار الميداني للنظريات (الأسبوع 6–16، بالتوازي) — 🔧 البنية جاهزة

**الهدف:** ملء مستوى الإثبات **"D — Local field-tested"** الفاضي. سد البقعة العمياء #2.

**المُنفَّذ في هذا الإصدار:** حقول `field_tests_count` / `field_test_result` / `last_tested`
على كل نظرية في السجل + الـ CSV.

**المنهجية:** 5 نظريات أولى للاختبار (loss_aversion، anchoring، social_proof، scarcity، peak_end_rule):
- اختبار A/B موثق في حملات حقيقية: Variant A = الصيغة المصرية من السجل، Variant B = رسالة محايدة
- حد أدنى 3 حملات لكل نظرية قبل الحكم
- الناجح يترقى لمستوى D، والفاشل يُوسم بشفافية

**KPI:** ≥ 3 نظريات بمستوى D بأدلة موثقة.

## المرحلة 4 · إصلاح المدخلات الذاتية والـ Heuristics (الأسبوع 8–14) — 🔧 جزء منفذ

**المُنفَّذ في هذا الإصدار:** استبدال درجة التمايز "الكلامية" بـ **DifferentiationAsset Matrix**:
7 أصول تمايز، كل واحد Boolean + دليل إلزامي (لينك/مستند) — الكلام المفتاحي ما بقاش يرفع الدرجة.

**المتبقي:**

| # | المهمة | معيار القبول |
|---|--------|---------------|
| 4.1 | Rubric مكتوب لكل درجة ذاتية (Taha Index، Persona Completeness، Founder OS) | وصف سلوكي ملموس لكل درجة 0–10 |
| 4.2 | اختبار توافق مُقيّمين على 10 طلاب | Krippendorff's α ≥ 0.7 |
| 4.3 | استبيان سلوكي لـ Founder OS بدل التقدير العام | تقليل تحيز المجاملة |

## المخاطر وخطط التخفيف

| الخطر | الاحتمال | التخفيف |
|-------|----------|----------|
| بيانات النتائج ناقصة (طلاب بيختفوا) | عالي | حافز: تقرير أداء شخصي مجاني مقابل إكمال البيانات + تذكير أسبوعي أوتوماتيك |
| العينة صغيرة فالمعايرة مش موثوقة | متوسط | حد أدنى 25 نتيجة + حد ±20% للتغيير + تشبع قوة البيانات عند 200 |
| الاختبارات الميدانية تعطل الحملات | متوسط | A/B على الرسالة مش على الميزانية في حملات قائمة |
| تسريب بيانات طلاب | منخفض | تجهيل SHA-256 إلزامي في السجلات + موافقة مسبقة |
| تضارب المعايرة مع خبرة المؤسس | متوسط | Prior بايزي = خبرتك؛ البيانات بتعدّل مش بتلغي — وقرار الاعتماد النهائي ليك |
